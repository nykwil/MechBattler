# Archive

What lands here:

- **Completed plan documents**, once every milestone in them has shipped. Status
  headers inside each doc say what shipped and when.
- **Dated design/plan pairs** from a single piece of work (`2026-08-24-component-height-design.md`).
- **Historical records** — material that was true once and is worth keeping for the
  reasoning, but is no longer current (`2026-07-status-record.md`).
- **`submission/`** — the July 2026 Build Week materials: tuning report, demo
  script, Devpost copy and its checklist. The deadline has passed; the evidence is
  kept because `TUNING-REPORT.md` is the write-up of that balance pass.

Code comments cite the archived plans by bare number — `docs/08 §2`, `docs/09 M2`,
`docs/10 M4` — because renumbering a citation is churn with no reader benefit. They
mean `archive/08-playable-battle-plan.md`, `archive/09-ux-diagnostics-plan.md` and
`archive/10-run-structure-plan.md`.

Living specs (00–06), the spatial-construction contract, the status/handoff doc
(07) and the active docs 11–19 stay at the top level; only finished work moves.
Numbering is never reused.
